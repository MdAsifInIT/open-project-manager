### Quality Pillars

#### 1. Dependency Compatibility
- Treat existing manifests and lockfiles as authoritative. Use compatible stable/LTS versions for newly requested dependencies; never perform unrelated upgrades.

#### 2. Minimal Required Changes
- Implement only the minimum best-practice change required for each task. No unsolicited refactors.

#### 3. Maintainability & Readability
- Follow existing project naming conventions and structure. Prefer clarity over clever abstractions.

#### 4. UI & Visual Integrity
- Never alter UI layout, spacing, typography, or components unless explicitly instructed.
